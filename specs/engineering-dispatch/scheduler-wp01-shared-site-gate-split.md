Status: **Owner approved option 3 on 2026-11-15, Gate 1 only; NOT IMPLEMENTED / NOT ACCEPTED.** Scope is the existing Draft [PR #1441](https://github.com/physicslu/plasma/pull/1441), after the third [admission-gap evidence](scheduler-wp01-admission-gap.md). This is a bounded implementation decision, **not a Gate 2 approval**.

## 1. Problem to solve, without concealing the trade-off

The current `ProgrammingBatchCoordinator._start()` consumes the canonical `start_id` and journals a Batch before any initial Platform callback completes. A late callback returning `SHARED_CONTROL_FAILURE` becomes an accepted Batch, whereas the pre-concurrency contract requires 503 with no consumed token or Batch when global Manager admission authority was already unusable. Yet waiting for the old unified callback's answer from a slow PPU prevents an independent healthy PPU's first POST. Both guarantees cannot hold while a single unresolved callback can veto the **entire** Batch.

**Approved direction:** split *what can invalidate Manager-wide authority before admission* from *what judges one PPU/Site's current readiness*. Do not relabel a genuinely ambiguous shared-control failure as a local fault, use stale cached approval, or fake an earlier HTTP refusal after an accepted Job.

## 2. Source-backed decomposition to implement and prove

| Gate | Scope / when | Source facts and permitted outcome |
| --- | --- | --- |
| **G0: Manager-shared authority and state** | Once synchronously **before** `consume_batch_start`, and again at submission transitions | Source-backed local guards: Manager `registry_store`, `poller`, `bootstrap_coordinator` as currently checked by `BootstrapPlasmaManagerHandler.platform_gate_reason`, plus Batch/Run shared-control and Journal latches; validate complete Target Set, commissioning, Route specification, Start-token admission, incompatible existing Batch. No network/PPU/bootstrap-status/fleet observation is allowed under the G0 pre-acceptance critical section. Missing/unjudgeable shared control **fails closed with the original relevant HTTP refusal**; no Batch, consumed token or Job. An object being non-null alone does not prove health: audit the actual shared-control/authorization state and define falsifiable evidence. |
| **G1: PPU Platform / Target readiness** | Per PPU (Platform once per PPU on initial admission), per Site (Target independently); repeat immediately before each operation | Existing `_platform_mutation_block(alias)` reads PPU-specific durable Platform state, active execution and current trusted fleet observation; `workflow.target_block(alias,site)` reads PPU Gateway health/status, specific Site idle/owner/Resource/Asset Set. Slow/unreachable/invalid **local** state blocks that PPU/Site only, never silently authorizes a write. A failure proven to implicate shared Manager control routes to G0/global latch, not to local `BLOCKED`. |
| **G2: Commit/submit transition** | Every new attempt under existing shared journal/dispatch lock | Re-evaluate shared failure latch and safe readiness/lease/Resource/Active Set. Journal planned and `starting` boundary before exactly one `Start`/POST; release lock before remote I/O. If an authority check fails **after** durable acceptance, retain consumed token and truthful read-only reconciliation, stop new global dispatch, observe accepted Jobs, keep possible-sent `OUTCOME_UNKNOWN`, no resends. Never report retrospective 503/no admission. |

The current production callback `BootstrapPlasmaManagerHandler.platform_gate_reason(alias)` already mixes (a) **class-scoped** missing `registry_store/poller/bootstrap_coordinator`, returning `SHARED_CONTROL_FAILURE: MANAGER_CONTROL_PLANE_UNAVAILABLE`, with (b) **per-alias** `_platform_mutation_block(alias)`, translating a failed PPU read to `TARGET_STATE_UNAVAILABLE` and maintenance/busy to `TARGET_NOT_READY`. This is a candidate seam, **not proof of complete authority coverage**. Audit whether any other callback, policy exception, auth store, poller fault, bootstrap/fleet dependency or shared gate can fail globally after an apparently passing G0. If failure origin is not provable, fail closed and document the exact unresolved case; do not treat an arbitrary user-injected `SHARED_CONTROL_FAILURE` as per-target.

A minimal design may introduce one explicitly named, injectable `shared_control_gate` / `shared_admission_check` for production wiring in `bootstrap_server.py` and test fakes. The injected test Platform callback may still report dynamic `SHARED_CONTROL_FAILURE` **after** accepted admission; distinguish this from an initial G0 refusal rather than rewriting all tests to accept every failure. Favor source-backed checks and existing gate/lock objects over a second engine or new endpoint.

## 3. Required external behavior / test oracles

1. **G0 unavailable before acceptance:** request rejected with existing precise error, including prior 503 `manager_shared_control_failure` case; `start_id` remains issued/unconsumed (read-only reconciliation reflects that state), no Batch journal delta, no Job. After repaired G0, a still-valid start may be tried once under normal rules. Duplicate/timeout/invalid Target semantics remain source-compatible.
2. **G1 target/PPU unavailable:** valid Batch accepted/journalled, `start_id` consumed; only affected Site(s) `BLOCKED`; independently healthy PPU/Site may POST and finish. Never infer release from timeout or PPU error.
3. **Held remote G1 readiness, Plan, Start:** deterministic event-controlled healthy peer POST **before held call release** for cross-PPU cases, and for independent Site-specific checks on the same PPU; shared PPU-wide maintenance state intentionally gates all Sites of that PPU. Test 1/2/8 lanes; no reliance on sleep timing; old serial approach must fail negative control.
4. **Global G0 degrades after durable acceptance:** Batch remains accepted and reconcilable; global latch blocks any new reservations/submissions before crossing the durable boundary; already accepted Job observed, never cancelled, resent or fabricated PASS. Record whether a Job was actually accepted or possibly sent; preserve PPU-wide unknown latch.
5. **Ambiguous failure-domain exception:** negative test proves no unrelated PPU Job is dispatched until domain is authoritatively classified; no silent G1 downgrade.
6. **Restart, persistence and retry:** `start_id` rollback/consumption, Journal-before-Start/POST, unknown recovery, StopQueuing, SAME Site exclusivity, matching owner/Resource/Image/Active Set, failure stop thresholds, SAFE_OFF-only Retry and single-Site Flash regression.
7. **User-facing schema:** retain `POST /api/programming/batches`, `GET /api/programming/starts/{start_id}`, EMode/PMode Manager ownership and `repeat=1`. Do not amend existing API status codes or tests merely to quiet a failing assertion. If explicit wire behavior must change, publish a precise ADR and migration proposal as **BLOCKED**, not as implicit implementation.
