## Test target and qualification boundary

```text
loads_fpga=false
```

Running `verify z2-ps` as unprivileged user `xilinx` initially reported:

The root verifier passed. This is recorded as a verifier diagnostics/usability defect: permission denial is currently indistinguishable from a missing canonical file for an unprivileged caller. It is not treated as a Runtime qualification failure and is intentionally deferred to a separate PR.

## Controlled activation-failure rollback — pending physical execution

This PR adds a qualification-only coordinator option:

```text
--qualification-fail-health-check
```

It is deliberately **not** routed through the normal `plasmactl z2-ps`, Console, Manager, or Bootstrap HTTP operator surface. The option is available only on the kit-local deployment coordinator and requires an existing previous release before a transaction starts.

The injection occurs when the installer calls the post-activation health check. At that point the candidate activation path has already been entered, so the production installer—not the qualification harness—must execute its normal rollback path.

The physical rollback gate is complete only when all of the following are retained as evidence:

```text
candidate activation returns failure
journal state=rolled_back
error_code=activation_failed_rolled_back
previous known-good release restored as /opt/plasma/current
/etc/plasma/ppu.yaml digest unchanged
Server/Gateway/helper healthy after rollback
sudo plasmactl verify z2-ps PASS on restored release
reboot retains restored release
post-reboot verifier PASS
```

Do not substitute file deletion, symlink corruption, Ethernet removal, arbitrary process killing, or an invalid release archive. Those test different failure classes and do not prove deterministic activation rollback.
