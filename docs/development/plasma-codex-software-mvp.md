## Fixed source scope and acceptance

The Codex Worker must create exactly one NEW file, with no tracked edits:

    examples/hello-world/main.c

- The owner/comment/issue/repository/main SHA are independently verified.
- Codex must run on the existing dedicated SWPC-plasma-codex self-hosted
  Runner as Linux user plasma-codex, using its existing authenticated
  ChatGPT/Codex CLI login, not a GitHub-hosted API key.
- The one-file source is limited to the tiny grammar: stdio.h,
  int main(void), exactly one puts("Hello, World!") or
  printf("Hello, World!\n"), and return 0. Other functions, includes,
  macros, comments, OS, network and device access are rejected.
- Worker actually compiles the file using GCC -std=c11 -Wall -Wextra
  -Werror -pedantic -O0. No diagnostics are allowed.
- Worker executes the compiled binary: exit 0, stderr empty, and stdout
  byte-for-byte Hello, World! followed by one LF byte (0x0a).
- All checks must pass before SHA256-bound patch artifact is uploaded.
- A separate GitHub-hosted Publisher verifies trusted GitHub event,
  patch SHA256, one new file path/mode and restrictive C grammar,
  without running the model-generated C code or having model credentials.
  The publisher creates a GitHub PR and stops before owner Gate 2.
- Native GitHub Actions GITHUB_TOKEN-created PRs may not trigger the usual
  PR CI events. The owner must explicitly verify CI, not presume it ran.

software-write job NO-GO if isolation cannot be verified.

merging are authorized. Codex has read-only GitHub access and the
Publisher has the PR write token but never model-login credentials.
