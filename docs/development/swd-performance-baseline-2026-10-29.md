# SWD performance measurement baseline (Gate 1)

This development measurement is based on `main` e5b310a17f0fea8cef9d6a1aad6947bb74f202be and the unmerged Native C WordPort diagnostics PR #1200 at 699b9b794057379a4f3c6d2a7279ced7c7deb3ef. The A/B archive `<SWPC_AB_EVIDENCE_ROOT>/20261028T144418Z-3434822` records four successful erase/program/verify/readback attempts. Its program-operation wall times were 93.726 and 94.125 seconds for v0.1 (18,768 bytes), and 285.925 and 286.348 seconds for v0.2 (62,800 bytes). Those are end-to-end operation times; the archive has no reliable per-stage or SWCLK-rate measurements. The archived engine SHA256 is `debcc7145b7815b8821f0dcf0dcb6d09f1bc0e804b733451cc89767a7b32df4e`.

The instrumentation adds a private stage-control UNIX socket between OpenOCD Jim Tcl and the PS-local WordPort bridge. OpenOCD waits for an `OK` reply at each `BEGIN`, `END` or `FAIL` marker. The bridge writes `stages.jsonl` with `time.monotonic_ns()`, UTC nanoseconds and cumulative MMIO and Remote Bitbang counters. `performance.json` records Preflight, Erase, Program, Verify, Readback or Reset, plus all remaining wall time as `other_duration_s`. Program and Reset are separate OpenOCD sessions. The accepted result requires all expected stages, nonnegative residual counters, a reconciled total and the existing readback SHA256 check.

`wire_bytes` counts received Remote Bitbang command bytes. `socket_recv_calls` and `socket_sendall_calls` count application calls, not kernel system calls. MMIO reads and writes come from Native C state. Each Native C drive/sample performs one DMB; the stage DMB count is derived as MMIO writes plus reads. The three initial Native C admission reads appear outside stages. WAIT, FAULT and retry counts remain `NOT_OBSERVED` because this bridge does not decode SWD responses. These metrics cannot be interpreted as SWCLK frequency or transaction rate without additional decoding.

The target configuration specifies a 4,096-byte SRAM working area. The report records this as `working_area_configured_bytes`; actual working-area allocation, Flash Loader execution, FIFO size/batches, fallback and erased-page count remain `NOT_OBSERVED` unless independently observed. `erase_pages_planned` follows the 1,024-byte STM32F1 page geometry. `verify_image` and `dump_image` remain separate commands; the instrumentation does not change their algorithms, retry policy, adapter speed, firmware, FPGA RTL or DUT wiring.

Before a physical A/B run, pin the exact instrumented engine SHA and every staged bundle file hash, complete hosted CI, obtain the existing owner/SHA-bound guarded-hardware Work Order, and verify current Boot ID, Root source pin, FPGA Image/Manifest, Site 1 lock, ownership, recovery, wiring and voltage. Stage only in `<Z2_BUNDLE_ROOT>/plasma-swd-performance-20261029`; do not replace the installed baseline. Run v0.1 and v0.2 once each with the same configuration and preserve OpenOCD log, bridge log, stage JSONL, performance JSON, receipt, firmware/readback SHA256 and LA capture if obtained. A native LA2016 Busy response or unavailable capture must not turn an unmeasured SWCLK rate into a claim.
