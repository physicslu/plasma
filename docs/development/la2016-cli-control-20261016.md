# KINGST LA2016 — SWPC CLI control and capture, 2026-10-16

**Observation, not physical timing qualification.** The HIL bench uses a KINGST LA2016 on the Transcend USB hub's **physical Port 4** (USB VID:PID `77a1:01a2`). The other USB ports are a shared-resource boundary: **Port 2** Z2 JTAG/UART; **Port 3** Z2 test Ethernet. Do not cycle the hub or interfere with those ports when the Z2 HIL agent is running.

## Observed PASS

- Ubuntu enumerated the Kingst USB device. KingstVIS GUI was previously **Connected**.
- Distribution `sigrok-cli`/`libsigrok` did **not** advertise the Kingst driver. A separate, user-local sigrok nightly AppImage **did** advertise `kingst-la2016` without replacing the system installation.
- A first `--driver kingst-la2016 --scan` failed to claim USB interface. Inspection using `ps` and `fuser` showed **KingstVIS held the LA's current USB device node**. After clean `SIGTERM` of the verified KingstVIS PID, `fuser` cleared and the CLI discovered `Kingst LA2016` with **CH0..CH15 and PWM1/PWM2**.
- A real CLI acquisition with `samplerate=1m`, `CH0,CH1` and `--samples 100000` exited **0** and produced a valid `.sr` file. Reading its metadata via `sigrok-cli --input-file ... --show` reported **1,000,000 samples/s, 16 logic channels, 2-byte unit size and 102,496 samples**. The output archive was **644 bytes**, consistent with highly compressible data, not independently validated timing.
- **All digital probes were physically floating** (no DUT, Z2, test generator or known signal attached). The acquired samples establish the USB driver/capture path only: they do **not** establish valid waveform amplitude, transitions, frequency or jitter.

## Reproduction on SWPC

Use the **verified** copy of the standalone AppImage. Never pass `ftdi-la`/Xilinx TUL to sigrok: that interface is the PYNQ-Z2 JTAG/UART, not the Kingst.

```bash
# From the operator-owned LA tool directory, with KingstVIS closed:
./sigrok-cli.AppImage --driver kingst-la2016 --scan

mkdir -p captures
OUT="captures/la2016-smoke-$(date +%Y%m%dT%H%M%S).sr"
timeout 20s ./sigrok-cli.AppImage \
  --driver kingst-la2016 --config samplerate=1m \
  --channels CH0,CH1 --samples 100000 --output-file "$OUT"
rc=$?
printf 'Capture exit code: %s\n' "$rc"
if [ "$rc" -eq 0 ]; then
    ./sigrok-cli.AppImage --input-file "$OUT" --show
fi
```

Do not infer exactly 100000 samples from the request; downstream code must read **actual** archive metadata. If the GUI or another program owns the USB interface, release only the verified Kingst process, not all USB devices. Do not automatically `kill -KILL` arbitrary processes or power-cycle the shared hub.
