## Pinned Provider and actual admission gap

[OpenOCD `stm32f1x.cfg`](https://github.com/openocd-org/openocd/blob/9ea7f3d647c8ecf6b0f1424002dfc3f4504a162c/tcl/target/stm32f1x.cfg) and [`stm32f1x.c`](https://github.com/openocd-org/openocd/blob/9ea7f3d647c8ecf6b0f1424002dfc3f4504a162c/src/flash/nor/stm32f1x.c) were read at the locked 0.12.0 commit. Their Git blob IDs match `openocd-0.12.0-stm32f1-source-lock-v1.json`. The driver maps `0x414` to 2 KiB High pages and max 512 KiB, and `0x430` to 2 KiB XL pages and max 1024 KiB. It reads flash size at `0x1ffff7e0`; invalid/unreadable size falls back to family maximum, which cannot by itself attest an exact F/G capacity. `0x430` sets dual-bank mode: Bank 1 512 KiB, Bank 2 reported total minus 512 KiB at `0x08080000`, with the second controller register base `0x40022040`. Erase and write select the bank's register base and require a halted target; write is halfword aligned with an asynchronous loader or slow halfword fallback. Read/verify use the OpenOCD flash framework. Protection/option-byte commands operate through Bank 1 and are outside the proposed qualified operation set. A bank-local full-range erase can invoke mass erase, so cross-bank erase semantics need explicit range validation. Rev 1/A errata, invalid-size fallback, protection state, boot option effects, out-of-range and cross-bank transitions need a bounded XL contract.

The upstream CFG creates **one** `stm32f1x` bank at `0x08000000`; it does not register Bank 2. The minimal candidate [`stm32f103xl.cfg`](../../data/ic-support/target/stm32f103xl.cfg) sources it and declares a second, probe-sized bank at `0x08080000`; it is a Host-only source candidate, not installed in any PPU OpenOCD scripts root. The pinned OpenOCD [Flash framework](https://github.com/openocd-org/openocd/blob/9ea7f3d647c8ecf6b0f1424002dfc3f4504a162c/src/flash/nor/core.c) auto-probes banks by address; `flash_erase_address_range` iterates and segments across registered banks, and `flash_write_image` selects the corresponding bank by address. `dump_image`/readback accesses the contiguous address range. The existing PLASMA `flash_base`/`flash_size`/`erase_granularity` range checks accept an F/G total contiguous window; there is no demonstrated need for a new multi-bank schema or Bank Manager.

The concrete remaining gap is admission and capacity evidence. `scripts/ppu_site_adapter_abi5.py::_operation_argv` explicitly runs only `flash probe 0`; it never explicitly probes Bank 1 or compares both probed sizes to the exact F/G Profile. Auto-probe during Erase/Write can select Bank 1, but the preamble alone does not attest total capacity. The OpenOCD driver falls back to **1024 KiB** when the flash-size register is invalid/unreadable; the candidate CFG disables manual `FLASH_SIZE` override but cannot distinguish that fallback from a true G part. The Provider source lock and `openocd_software_qualification.py` bind `tcl/target/stm32f1x.cfg` and only Low/Medium/High reviewed groups; `catalog_sqlite_repository.py::_validate_data_only_l2` obtains those groups and requires the record's target CFG to equal the locked Provider CFG. No XL group, reviewed exact package route, or durable official-source packet exists. These are exact Provider/Admission limitations, **not** a dual-bank schema limitation. The minimum separate follow-up is to deliver and source-lock the XL CFG in the installed OpenOCD scripts, bind an XL qualification group and exact package evidence, and explicitly probe/compare both banks with fail-closed invalid-size behavior before use. The owner asked for a proposal rather than changes to these code paths under this Gate 1; no production Python or `SUPPORTED` record is emitted.

## 2026-11-28 approved follow-up implementation

The preceding sections record the earlier audit at its historical baseline. This follow-up adds a source-locked XL extension to the existing OpenOCD 0.12.0 target route, a raw `0x430` device-ID and `0x1FFFF7E0` Flash-capacity check before either bank probe, and page-range segmentation that prevents a full-bank request from entering the driver's mass-erase path. The single contiguous `FlashProfile` remains the execution model. Existing E/P/V/R, Schema, Provider, and SQLite Publisher paths are reused. The source-backed software qualification covers exactly 20 F/G ICPNs: 15 LQFP and five LFBGA144. Historical 77 L3 qualifications retain their evidence and level. The reviewed ST PDF text is documentary evidence; original PDF bytes and their hashes remain **NOT_ATTESTED**. This qualification claims no installed runtime, DUT, Site, electrical, or physical programming result.

The isolated SQLite acceptance constructs the pre-follow-up L1 snapshot, validates and publishes all 20 L2 rows in one revision, repeats publication idempotently, checks unchanged L3 objects, and rolls back to the initial digest. Invalid capacity, Provider, package, and package-route packets fail before stage. PR CI is configured to parse the installed two-bank CFG using the pinned OpenOCD 0.12.0 x86 binary without `init` or hardware contact. Until that job runs at the updated PR HEAD, pinned binary execution is **NOT_RUN**.
